# pi-wgpu-rebuild · 问题与范围（L1）

## 问题

自有 3D 引擎要只维护一套渲染代码，同时运行于 Windows 桌面、Android、微信小游戏。团队选定按 WebGPU 风格接口（wgpu 形接口）编码，但该接口在存量设备图形栈上无法直接使用：微信小游戏仅提供 WebGL2（iOS 需 ≥15.5）、存量 Android/Windows 主力仍是旧一代驱动。因此需要一个「对外给 wgpu 形接口、对内运行于旧图形驱动」的内置渲染实现，并保留开关让同一份上层代码在自建实现与官方参考实现间切换对照排差。

## 在范围内

渲染库本体：对外兼容接口子集、渲染状态与驱动指令下发、三驱动形态落地（Windows/浏览器验收先行、Android 编译链就绪）、冒烟与验收样例、确定性的资源对象面（创建/持有/删除时机）。

## 不在范围内

- **业务资产管理（资产键值复用、显存记账、异步加载、超时/容量收缩）**：引擎生态上游资产 crate 在本库公开 API 之上承接（L5 门禁校准拍板 2026-10-13）；本库恒为渲染状态与下发的直替层——写清 OUT 防下游当默认已含。
- **Compute、GPU→CPU 回读（截图/取像素）**：引擎不用；回读在多平台性能/一致性差。轮1 拍板维持不做。
- **多渲染目标、多重采样目标、indirect/multi-draw、RenderBundle、QuerySet/时间戳、push constants、SPIR-V 输入、缓冲区映射族**：目标驱动栈不支持或上层无需求，实现与验证成本远超收益。
- **非 GL 系后端、官方验证层语义复刻**：与定位（薄执行层）冲突。
- **上层引擎业务与新增样例能力**：样例仅服务于冒烟与验收。
